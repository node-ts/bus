# bus-docs

The source of the consumer docs at https://bus.node-ts.com, built with [VitePress](https://vitepress.dev). This file is for people writing the docs; it isn't published. How to run and deploy the site is in the Docs section of [CONTRIBUTING.md](../CONTRIBUTING.md#docs).

```sh
pnpm build             # the packages, which the snippets and API reference are built from
pnpm docs:dev          # http://localhost:5173, reloading as you edit
pnpm docs:typecheck    # type check every snippet against the built packages
pnpm docs:build        # build to docs/.vitepress/dist; fails on dead links
pnpm docs:check-redirects
```

## Layout

| Path                          | What's there                                                                                               |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `index.md`                    | The landing page (`layout: home`)                                                                          |
| `getting-started/`, `guide/`  | Pages, one markdown file each. A page with children, such as `guide/workflows.md`, sits next to its folder |
| `transports/`, `persistence/` | Adapter pages, with `transports.md` and `persistence.md` as their overviews                                |
| `upgrading/v2.md`             | Renders the repo's `MIGRATING.md`, which stays the single source                                           |
| `api/`                        | Generated by typedoc from each package's root exports at build time. Not committed; don't edit it          |
| `snippets/`                   | Every TypeScript snippet the pages show                                                                    |
| `public/`                     | Files served as they are: brand assets, diagrams, `_redirects`                                             |
| `.vitepress/config.mts`       | Navigation, sidebars, search, `llms.txt` and the head tags                                                 |
| `.vitepress/theme/`           | The custom theme: brand styles in `style.css`, and the components below                                    |
| `scripts/`                    | The redirect check, and the old site's sitemap it checks against                                           |
| `typedoc.json`, `typedoc/`    | The API reference config, and a plugin that fails the build on a `{@link}` that doesn't resolve            |

A new page needs an entry in the sidebar in `.vitepress/config.mts`, in the section it belongs to: Getting started, Guide, Transports, Persistence or Reference.

## Page template

Every page follows the same shape. [`guide/messages/events.md`](./guide/messages/events.md) is a good one to copy.

```md
---
title: Events
description: One sentence for search results, social cards and llms.txt.
---

# Events

One paragraph: what the page covers and when you'd use it.

## A section

The content, with snippets from docs/snippets.

<<< @/snippets/events.ts#publish

## See also

- [Commands](/guide/messages/commands)
- [`handlerFor`](/api/bus-core/functions/handlerFor) in the API reference
```

Frontmatter:

- `title` (required): the page's title, as in the sidebar.
- `description` (required): one sentence, used for the meta description, social cards and `llms.txt`.
- `outline` (optional): the heading levels in "On this page", such as `[2, 2]`. The default is `[2, 3]`.
- `next` / `prev` (optional): only on the last or first page of a section, to link across sections.

Write in plain, short sentences. Link to other pages with root-relative paths without `.md`, such as `/guide/workflows`, and to the API reference for the details of a type. The build fails on a link to a page that doesn't exist.

## Snippets

Every TypeScript code block comes from a file in `snippets/`, so that `pnpm docs:typecheck` checks it compiles against the packages. Don't write TypeScript inline in a page. Shell commands, JSON and other languages can stay inline.

- Write snippets the way an app would: import from the package roots, and import messages from `snippets/messages`. `snippets/services` and the `*-client.ts`/`*-store.ts` files are stand-ins that pages don't show.
- Show a whole file with `<<< @/snippets/file.ts`, or part of one with `<<< @/snippets/file.ts#region`, marking the part with `// #region name` and `// #endregion name`. Add `[Label]` after it to title it in a code group.
- A bus that receives messages needs `.withMessageTypes(messageTypes)`. After adding or changing a message or workflow state in `snippets/`, run `pnpm --filter bus-docs run generate:message-types` and commit `snippets/message-types.generated.ts`.
- Snippets are linted and formatted like the rest of the repo.

## Components

Pages may use these components, registered globally in `.vitepress/theme/index.ts`, and no others. Leave a blank line inside a component around markdown content.

| Component                                           | Use it for                                                                         |
| --------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `<FeatureGrid>` with `<Card title link tag>` inside | Section overviews and the landing page: a grid of linked cards                     |
| `<Steps>` around an ordered list                    | A procedure, such as installing something. Start each item with a bold title       |
| `<PackageBadge pkg="bus-sqs" />`                    | The top of an adapter page: the package name, its npm version and its source       |
| `<Diagram src alt caption />`                       | A committed SVG from `public/diagrams/`. `alt` describes what it shows             |
| `::: code-group`                                    | Tabs: npm, pnpm and yarn commands, or the function and class versions of a snippet |
| `::: tip`, `::: info`, `::: warning`                | Callouts                                                                           |

Diagrams are hand-written SVG with a white background and the brand colours, so they read in light and dark mode.

## Brand

The logo (`public/logo.svg`, also `favicon.svg`), the social card (`public/og.svg`, rendered to `og.png`) and the teal accent (`--bus-*` in `.vitepress/theme/style.css`) are placeholders, made to be easy to replace. To rebrand, replace the SVGs, re-render `og.png` from `og.svg` (the command is in the file), and change the colours in `style.css`.
