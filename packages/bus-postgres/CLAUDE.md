# bus-postgres

Postgres persistence for workflow state. Read the root `CLAUDE.md` first.

- **Config** (`src/postgres-configuration.ts`): `{ connection: pg.PoolConfig, schemaName: string }`. The constructor also accepts a `Pool` you pass in.
- **Tables**: one per workflow state, `"<schemaName>"."<state.$name>"`. The name is stripped of invalid characters and lowercased _before_ snake-casing, so `TestWorkflowState` becomes `testworkflowstate`. Changing this renames existing tables.
- `initialize()` creates the schema. `initializeWorkflow()` runs `create table if not exists (id uuid pk, version int, data jsonb)`, then adds an `(id, version)` index and one partial expression index per distinct `mapsTo`. The indexes use `DO $$ … to_regclass` blocks so it works on Postgres 9.4+, and it must be safe to run more than once and from several processes at once (`createIfMissing` treats the duplicate errors of a concurrent create as success).
- **Index names** are `<schema>_<table>_<fields>_idx` when that fits in 63 bytes (Postgres truncates longer identifiers). Longer ones are truncated and end in a hash of the full name (`resolveIndexName`), and an index with the same keys under the old truncated name is reused rather than duplicated (#310). Don't change names that fit: deployed databases have them.
- State is stored as JSON in `data` (`JSON.stringify(state)`; the bus passes plain JSON values and restores the classes it reads back with its own serializer and message types). Lookup is `data->>'<mapsTo>' = $1`, and `data->>'$name'` equal to the state's `$name` (states whose table names collide share a table, #315), restricted to `$status = 'running'` unless `includeCompleted` is set. Only the lookup value and `$name` are bound parameters. `mapsTo` is inlined with `escapeLiteral` so the query expression matches the secondary index; don't turn it into a bind parameter.
- **Optimistic concurrency**: when `$version === 0` it inserts. Otherwise it runs `update … where id = $ and version = <old>`, and if no row is updated it throws `WorkflowStateNotFound` (`src/error/`). `WorkflowRegistry` rethrows that error, so the message is retried.
- **Outgoing messages** (delayed delivery and the transactional outbox): `initialize()` also creates `"<schemaName>"."outgoing_messages"` (`id text pk, kind, destination text null` (only replies have one), `message/attributes/headers jsonb, due_at, available_at timestamptz, attempts int`) and an index on `available_at`, which is the due time or the end of the current lease, so leased rows don't slow claims down. Stores go through one `jsonb_to_recordset` parameter, set `available_at` to `greatest(due_at, clock_timestamp() + lease_ms)` when a `leaseMs` is given (`clock_timestamp()`, since `now()` is the transaction's start), with `on conflict (id) do nothing returning id` (the ids not returned are duplicates); claims are one `with … for update skip locked` + `update … returning` statement that compares with `now()` unless a `now` is passed, increments `attempts` and leases for `least(leaseMs * attempts, maxLeaseMs)`. Rows are only deleted once sent. Both live in module-level `insertOutgoingMessages`/`claimOutgoingMessages` taking a `Pool | PoolClient`, so `beginTransaction()` runs them on its client; keep them unexported. Delayed delivery needs Postgres 9.5+. Tests that drop the `workflows` schema without `cascade` must drop this table first.
- **Transactions** (`withOutbox()`, `src/postgres-persistence-transaction.ts`, internal, the exported accessor in `src/postgres-transaction.ts` and `src/postgres-test-transaction.ts`): `beginTransaction()` checks a client out of the pool and runs `begin` (destroying the client with `release(error)` if that fails), then returns a `PostgresPersistenceTransaction` whose workflow and outgoing queries run on that client through the same private `queryWorkflowState`/`writeWorkflowState` and `insertOutgoingMessages` the pool uses (all take a `Queryable`). `commit`/`rollback` release the client, or destroy it if the statement fails; `commit` throws `TransactionRolledBack` when Postgres answers `commit` with `ROLLBACK` (a statement failed earlier, even if a handler caught it). Every later call throws `TransactionNotActive` (`Ended`). `postgresTransaction(ctx)` returns a frozen `{ query }` (`PostgresTransactionClient`) that checks the transaction is still active on each call, so a kept client can't run in another message's transaction; it throws `NoTransaction` / `OtherPersistence` otherwise. `postgresTestTransaction(fakeClient)` wraps a fake `{ query }` with no-op operations for unit tests. Handlers share the client, so no savepoints or `begin`/`commit` in handlers. Each message being handled holds a client, so the pool needs more than the bus' concurrency, and handlers that query the pool directly can deadlock.
- **Identifiers**: every schema, table and index name goes through `pg`'s `escapeIdentifier` (and `escapeLiteral` inside `to_regclass`), so `schemaName` is case-sensitive. `initialize()` throws `InvalidSchemaName` for an empty name. Only `beginTransaction()` checks a client out; every other query goes through the pool.
- **Tests**: `postgres://postgres:password@localhost:6432/postgres` (override with `POSTGRES_URL`), schema `workflows`. Start a database with `docker compose up -d postgres` from the repo root. Fixtures are in `test/`, which is copied into `bus-mongodb/test`; keep the two in sync.
