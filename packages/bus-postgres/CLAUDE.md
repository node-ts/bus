# bus-postgres

Postgres persistence for workflow state, and `PostgresTransport` (#266, see Transport below). Read the root `CLAUDE.md` first.

- **Config** (`src/postgres-configuration.ts`): `{ connection: pg.PoolConfig, schemaName: string }`. The constructor also accepts a `Pool` you pass in.
- **Tables**: one per workflow state, `"<schemaName>"."<state.$name>"`. The name is stripped of invalid characters and lowercased _before_ snake-casing, so `TestWorkflowState` becomes `testworkflowstate`. Changing this renames existing tables.
- `provision({ workflows, dryRun })` creates the schema, the outgoing messages table and its index, and per workflow runs `create table if not exists (id uuid pk, version int, data jsonb)`, then adds an `(id, version)` index and one partial expression index per distinct `mapsTo` (`resolveWorkflowIndexes`). Its plan lists `postgres-schema`/`postgres-table`/`postgres-index` resources and `GRANT` statements for `<runtime_role>`. `initialize({ workflows, verifyResources })` creates nothing: it checks the schema (`pg_namespace`), then every table and index in one `to_regclass` query over all candidate names (an index counts under its legacy name too), and throws `ResourcesNotProvisioned`. The indexes use `DO $$ … to_regclass` blocks so it works on Postgres 9.4+, and it must be safe to run more than once and from several processes at once (`createIfMissing` treats the duplicate errors of a concurrent create as success).
- **Index names** are `<schema>_<table>_<fields>_idx` when that fits in 63 bytes (Postgres truncates longer identifiers). Longer ones are truncated and end in a hash of the full name (`resolveIndexName`), and an index with the same keys under the old truncated name is reused rather than duplicated (#310). Don't change names that fit: deployed databases have them.
- State is stored as JSON in `data` (`JSON.stringify(state)`; the bus passes plain JSON values and restores the classes it reads back with its own serializer and message types). Lookup is `data->>'<mapsTo>' = $1`, and `data->>'$name'` equal to the state's `$name` (states whose table names collide share a table, #315), restricted to `$status = 'running'` unless `includeCompleted` is set. Only the lookup value and `$name` are bound parameters. `mapsTo` is inlined with `escapeLiteral` so the query expression matches the secondary index; don't turn it into a bind parameter.
- **Optimistic concurrency**: when `$version === 0` it inserts. Otherwise it runs `update … where id = $ and version = <old>`, and if no row is updated it throws `WorkflowStateNotFound` (`src/error/`). `WorkflowRegistry` rethrows that error, so the message is retried.
- **Outgoing messages** (delayed delivery and the transactional outbox): `provision()` also creates `"<schemaName>"."outgoing_messages"` (`id text pk, kind, destination text null` (only replies have one), `message/attributes/headers jsonb, due_at, available_at timestamptz, attempts int`) and an index on `available_at`, which is the due time or the end of the current lease, so leased rows don't slow claims down. Stores go through one `jsonb_to_recordset` parameter, set `available_at` to `greatest(due_at, clock_timestamp() + lease_ms)` when a `leaseMs` is given (`clock_timestamp()`, since `now()` is the transaction's start), with `on conflict (id) do nothing returning id` (the ids not returned are duplicates); claims are one `with … for update skip locked` + `update … returning` statement that compares with `now()` unless a `now` is passed, increments `attempts` and leases for `least(leaseMs * attempts, maxLeaseMs)`. Rows are only deleted once sent. Both live in module-level `insertOutgoingMessages`/`claimOutgoingMessages` taking a `Pool | PoolClient`, so `beginTransaction()` runs them on its client; keep them unexported. Delayed delivery needs Postgres 9.5+. Tests that drop the `workflows` schema without `cascade` must drop this table first.
- **Inbox** (`withOutbox()`, #261): `provision()` also creates `"<schemaName>"."inbox"` (`endpoint text, message_id text, processed_at timestamptz`, primary key `(endpoint, message_id)`) and `inbox_processed_at_idx` on `processed_at`, next to the outgoing messages DDL; it's always provisioned (in the plan, with `GRANT SELECT, INSERT, DELETE` for the runtime role) and `findMissingResources()` checks both, so a missing table fails `initialize()` with `ResourcesNotProvisioned` rather than every message. The transaction's `recordIncomingMessage` is module-level `insertIncomingMessage`: `insert ... values (..., clock_timestamp()) on conflict (endpoint, message_id) do nothing`, true when `rowCount === 1`. `on conflict` rather than catching a unique violation, which would abort the transaction; it blocks on a row another open transaction inserted, so concurrent copies wait for each other. `removeIncomingMessagesBefore(date, limit)` deletes one batch on the pool (`where ctid in (select ctid ... where processed_at < $1 limit $2)`) and returns `rowCount`; a missing table (42P01) is nothing to remove, logged at debug. `beginTransaction()` runs `begin isolation level read committed`, since under repeatable read or serializable a copy blocked on the inbox row fails with 40001 instead of seeing the conflict. Tests that drop the `workflows` schema without `cascade` must drop this table first.
- **Transactions** (`withOutbox()`, `src/postgres-persistence-transaction.ts`, internal, the exported accessor in `src/postgres-transaction.ts` and `src/postgres-test-transaction.ts`): `beginTransaction()` checks a client out of the pool and runs `begin isolation level read committed` (destroying the client with `release(error)` if that fails), then returns a `PostgresPersistenceTransaction` whose workflow, outgoing and inbox queries run on that client through the same private `queryWorkflowState`/`writeWorkflowState`, `insertOutgoingMessages` and `insertIncomingMessage` the pool uses (all take a `Queryable`). `commit`/`rollback` release the client, or destroy it if the statement fails; `commit` throws `TransactionRolledBack` when Postgres answers `commit` with `ROLLBACK` (a statement failed earlier, even if a handler caught it). Every later call throws `TransactionNotActive` (`Ended`). `postgresTransaction(ctx)` returns a frozen `{ query }` (`PostgresTransactionClient`) that checks the transaction is still active on each call, so a kept client can't run in another message's transaction; it throws `NoTransaction` / `OtherPersistence` otherwise. `postgresTestTransaction(fakeClient)` wraps a fake `{ query }` with no-op operations for unit tests. Handlers share the client, so no savepoints or `begin`/`commit` in handlers. Each message being handled holds a client, so the pool needs more than the bus' concurrency, and handlers that query the pool directly can deadlock.
- **Identifiers**: every schema, table and index name goes through `pg`'s `escapeIdentifier` (and `escapeLiteral` inside `to_regclass`), so `schemaName` is case-sensitive. `initialize()` and `provision()` throw `InvalidSchemaName` for an empty name. Only `beginTransaction()` checks a client out; every other query goes through the pool.
- **Shared SQL helpers** (`src/postgres-sql.ts`, internal): `RUNTIME_ROLE`, `assertValidSchemaName`, `qualifyName`, `createIfMissing`, `isUndefinedTableError`, `Queryable`. The persistence and transport both use them.
- **Transport** (`src/postgres-transport.ts`, config `src/postgres-transport-configuration.ts`, raw message `src/postgres-transport-message.ts`; design accepted on #266). Needs Postgres 13+ (`gen_random_uuid()`).
  - **Tables**, shared by every queue in `schemaName`: `transport_messages` (`id uuid, queue, body text` (the bus serializer's output), `attributes/headers jsonb, visible_at, deliveries int, lease_token uuid, sent_at`) with index `(queue, visible_at)`, `transport_queues (name pk)`, `transport_subscriptions (message_name, queue)` pk both, `transport_dead_letters (id, queue, body, attributes, headers, failed_at)`. `provision()` creates them and, unless send-only, inserts the queue row and a subscription per `getMessageNames()` + `getExternallyManagedTopicIdentifiers()` (`on conflict do nothing`); it never deletes. `messageNames` is unused: there are no per-message resources. `initialize()` checks schema, tables, index (`to_regclass`) and, unless send-only, the queue and subscription rows. Grants: messages SIUD, queues/subscriptions SELECT, dead letters INSERT (not send-only).
  - **Sending**: `send` and `publish` both fan out with one `insert … select from transport_subscriptions where message_name = $name` CTE, which also `pg_notify`s each queue reached; no subscribers logs a warning. `sendToAddress` inserts into the queue only if it's in `transport_queues`, else `EndpointNotFound`. Attributes are one jsonb column, headers another, so only `bus-failure` is reserved.
  - **Receiving**: a lease. One `with next as (select … for update skip locked limit 1) update … set visible_at = clock_timestamp() + visibilityTimeoutMs, deliveries + 1, lease_token = <new uuid>` statement. `failedAttempts = deliveries - 1` (an expired lease counts, like SQS). `deleteMessage`/`returnMessage`/`fail` all match `id` and `lease_token`, so a receipt whose lease another receiver took over settles nothing (warns). No heartbeat (maintainer's call): document `visibilityTimeoutMs` like SQS's visibility timeout. `fail` is one `delete … returning` → `insert into transport_dead_letters` statement adding the `bus-failure` header; `returnMessage` sets `visible_at`, clears the lease and drops `bus-failure`. Unparseable bodies are dead-lettered on read.
  - **Waiting**: `readNextMessage` claims, and when empty waits on `waiters` until woken; it loops until a message or `stop()`. After an empty claim it checks `isStarted` before waiting (a `stop()` during the claim already ran `wakeAll()`, so waiting would hang `bus.stop()`; #344 review), and consumes `wakePending` (set by `wakeOne()` when no read was waiting) by claiming again. One waiter is woken per poll tick (`pollIntervalMs`, default 1 s) and per notification (`wakeOne`, which sets `wakePending` when none waits), and a successful claim wakes only a read that's already waiting (`wakeWaiting`, no pending flag, since the worker claims again on its next read), so an idle process makes one query per tick whatever its concurrency. `LISTEN` runs on its own `pg.Client` (not the pool), built from `connection` or, for a pool passed in, `pool.options` plus `password` copied explicitly (pg-pool makes it non-enumerable, so a spread drops it), with `keepAlive` and a 10 s connect timeout unless one is configured, on channel `node_ts_bus_<md5(schema.queue)>`; the SQL side computes the same `md5`. Each listen runs through `startListening()`, which records it in `listening` for `stop()` to await, and takes the `listenGeneration` it began in; a listen whose generation is stale (a stop or start since) ends its own client. `stop()` takes and closes `this.listener` before awaiting the in-flight listen, so it never closes a listener a later `start()` made. A lost listener is logged and retried with backoff (1 s doubling to 30 s), which only resets when the connection had stayed up 30 s, while polling carries on; `listen: false` turns it off. `pollIntervalMs` and `visibilityTimeoutMs` must be positive (`InvalidTransportDuration`).
  - The transport ends only a pool it made (`ownsPool`), unlike the persistence. Delayed sends use the persistence's outgoing messages and the dispatcher (no core change). Joining the `withOutbox()` transaction for exactly-once is #343; don't claim exactly-once in docs until it lands.
- **Tests**: `postgres://postgres:password@localhost:6432/postgres` (override with `POSTGRES_URL`), schema `workflows`. Start a database with `docker compose up -d postgres` from the repo root. Fixtures are in `test/`, which is copied into `bus-mongodb/test`; keep the two in sync. The transport's tests (`src/postgres-transport.integration.ts`) use bus-test's fixtures and message types instead, and schemas of their own (`transport_*`), which they drop first.
