# bus-mongodb

MongoDB persistence for workflow state (mongodb driver ^7). Read the root `CLAUDE.md` first.

- **Config** (`src/mongodb-configuration.ts`): `{ connection: string, databaseName: string }`.
- **Collections**: one per workflow state, named the same way as Postgres tables (invalid characters stripped, lowercased). Documents look like `{ id, version, data }`.
- Keys in `data` are percent-escaped at every depth, including objects inside arrays (`src/key-encoding.ts`): `%` → `%25`, `$` → `%24`, `.` → `%2E`, so `$workflowId` is stored as `%24workflowId`. Decoding reverses it losslessly. Queries and indexes build mapped-property paths with the same `encodeKey`, via `resolveWorkflowStateFieldPath`; keep them in step.
- `resolveCollections(workflows)` lists the `outgoingmessages` and `inbox` collections and one per workflow state with their indexes. `provision()` connects (`client.connect()` is a no-op on a connected mongodb 7 client, checked in #237), creates each collection if it's missing and calls `createIndex` (a no-op if the index already exists) for `{ id, version }` and each `mapsTo` path; its plan lists `mongodb-collection`/`mongodb-index` resources and role privileges. `initialize()` connects and, with `verifyResources`, checks them with `listCollections`/`listIndexes` and throws `ResourcesNotProvisioned`. It never drops indexes, so user-added ones are safe. Index names keep the quoted `"<collection>_<fields>_idx"` form.
- **Outgoing messages** (delayed delivery and the outbox): an `outgoingmessages` collection with `_id` = message id, an index on `availableAt` (the due time, or the end of the lease once claimed, so leased documents don't slow claims down) created by `provision()`, and `message`/`attributes`/`headers` stored with encoded keys. Stores are pipeline upserts that `$replaceWith` a `$literal` document only when `attempts` is missing (a stored id is kept; ids missing from `upsertedIds` are returned as duplicates), so a lease's `availableAt` is `$max` of `dueAt` and `$$NOW + leaseMs`, on the database's clock. Claims read the server clock once (`hello`'s `localTime`, so the filter stays a plain indexed range rather than `$expr` on `$$NOW`) unless `now` is passed, then loop `findOneAndUpdate` (sorted by `availableAt`, a pipeline update that increments `attempts` and leases for `$min` of `leaseMs * attempts` and `maxLeaseMs`, `includeResultMetadata: true`) once per message, which is what makes concurrent claims safe. The integration test runs `scheduledMessageRoundTripTests` on its own database, since the file's running bus shares `workflows`.
- **Transactions** (`withOutbox()`, #323; internal `src/mongodb-persistence-transaction.ts`, the exported `mongoSession(ctx)` in `src/mongo-session.ts` and `mongoTestSession()` in `src/mongo-test-session.ts`): `beginTransaction()` starts a `ClientSession` and a transaction with `TRANSACTION_OPTIONS` (snapshot read concern, majority write concern, primary); nothing reaches the server until the first operation. Workflow, outgoing and inbox operations take an optional `session` and run in it. MongoDB fails operations sent alongside the one that starts a transaction (`ConflictingOperationInProgress`), so the transaction runs its first operation alone and the rest wait for it; after that the server serializes them. Any failed operation aborts the transaction on the server, so `commit` maps a `TransientTransactionError` (such as `NoSuchTransaction`) to `TransactionRolledBack`, and retries `UnknownTransactionCommitResult` for up to 120 s as `withTransaction()` does. Commit and rollback always end the session, and the driver rejects a kept session (`MongoExpiredSessionError`). `initialize({ outbox: true })` checks `hello` for `setName` or `msg: 'isdbgrid'` and throws `ReplicaSetRequired` on a standalone server.
- **Inbox** (#261): an `inbox` collection with a unique `"inbox_endpoint_messageId_idx"` and a TTL `"inbox_processedAt_idx"` (`expireAfterSeconds` = bus-core's `INBOX_RETENTION_MS`), always provisioned. `recordIncomingMessage` is a pipeline upsert setting `processedAt` to `$ifNull: ['$processedAt', '$$NOW']`, true when `upsertedCount === 1`, since a duplicate key error would abort the transaction. A record another open transaction inserted fails with a `WriteConflict` rather than blocking as Postgres does, so when the record is the transaction's first operation (every received message's), the transaction aborts, sleeps 5 ms doubling to 100 ms and starts again until the other one ends (up to 120 s); otherwise it throws. `removeIncomingMessagesBefore` is a real bounded delete (`find` up to `limit` ids, then `deleteMany`), as `inboxTests` requires; the TTL index does the routine removal, so it's a backstop.
- Existing deployments aren't migrated from the old `__` key scheme or index keys. The maintainer's call: nobody meaningfully runs this in production.
- **Optimistic concurrency**: `findOneAndUpdate({ id, version: <old> })`. It passes `includeResultMetadata: true` so every driver major (5.x defaults to it, 6+ does not) returns a `ModifyResult`, and an empty `result.value` throws `WorkflowStateNotFound`. Keep the option: without it a 6+ driver returns the bare document, so the check would throw on every update.
- mongodb 7.6+ does a dynamic `import('os')` during the handshake (NODE-7832), which fails under jest unless vm modules are on. `test.env` sets `NODE_OPTIONS=--experimental-vm-modules` for this alone; drop it once NODE-7832 ships.
- **Tests**: `mongodb://localhost:27017/workflows?directConnection=true` (override with `MONGODB_URL`; `docker compose up -d mongo` from the repo root). Mongo runs as a single-node replica set `rs0` in compose (`--replSet rs0`, initiated by the healthcheck with member `localhost:27017`) and CircleCI (`command: ['--replSet', 'rs0']`, initiated by `.circleci/init-mongo-replica-set.mjs` in the "Wait for integration infra" step), since the outbox needs transactions. `directConnection=true` keeps the client off the member's advertised host, so a replica set on another port works too. `afterAll` drops the database. The integration test runs `outboxTests` and `inboxTests` on databases of their own; `src/mongo-session.integration.ts` covers `mongoSession(ctx)`. Fixtures in `test/` are copied from `bus-postgres/test`; keep the two in sync.
