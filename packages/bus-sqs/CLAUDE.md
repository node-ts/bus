# bus-sqs

An SQS/SNS transport. Read the root `CLAUDE.md` first.

## Design

- **Fanout**: each message `$name` gets its own SNS topic, and the service queue subscribes to every topic it handles. `send` and `publish` both publish to SNS (`Subject` = `$name`). `readNextMessage` expects the SNS envelope (`body.Message`, `body.MessageAttributes`); a message with no envelope is deleted with a warning.
- **Naming** (`src/queue-resolvers.ts`): any character outside `[a-zA-Z0-9_-]` becomes `-`. The default DLQ name is `dlq`, not core's `dead-letter`. Only `resolveTopicName` and `resolveTopicArn` can be overridden, and they're applied in `initialize()`, so `publish` before `initialize` fails.
- **Config** (`src/sqs-transport-configuration.ts`): give either `queueArn`, or `awsAccountId` + `awsRegion` + `queueName`. Account and region are needed even in send-only mode. Defaults: `visibilityTimeout` 30, `maxReceiveCount` 15 (above the default policy's 10 attempts), `waitTimeSeconds` 10, `messageRetentionPeriod` 14 days (DLQ only). You can pass your own `SQSClient`/`SNSClient` to the constructor; tests do this to point at LocalStack.
- Both `initialize()` and `provision()` call `resolveResourceNames()` (queue/DLQ names, ARNs, URLs, topic resolvers) and `planResources()` (the bus' own topics for `messageNames` plus handled names; unless send-only, DLQ then service queue with their attributes, a subscription per handled topic and per external custom-handler topic (`external: true`), and the policy). External topics are never created, published to or granted `sns:Publish`.
- **`provision()`** (deploy time or `withAutoProvision()`): `CreateTopic` each topic → unless send-only, `CreateQueue` DLQ then service queue (`QueueAlreadyExists` ignored) → `Subscribe` → `SetQueueAttributes` with the `Policy` (`queuePolicy`, or `generatePolicy`, which allows any same-account SNS topic; always set, never at runtime) → sync attributes. The sync reads `VisibilityTimeout` and `RedrivePolicy` with `GetQueueAttributes` (which returns nothing unless `AttributeNames` is given) and sets only those that differ. `RedrivePolicy` is compared by its JSON entries because SQS doesn't keep key order or number types (don't sync `Policy` that way: nested objects compare as `[object Object]`). A dry run makes no calls. `runtimePolicy()` builds the IAM policy in the plan (`sns:Publish` on the bus' topics, or `resolveTopicArn(account, region, '<prefix>*')` when `sendsAnyMessage` (schedulers), where `topicNamePrefix()` finds a fixed prefix by probing `resolveTopicName` (empty when it isn't prefix + default name), receive/delete/visibility on the queue, `SendMessage` on the DLQ, `GetQueueUrl` (+ `GetQueueAttributes` with `verifyQueuePolicy`) on both, `ListSubscriptionsByTopic` on subscribed topics). After creating topics it fills `registeredMessages`, so an auto-provisioned publish doesn't `CreateTopic` again.
- **`initialize()`** creates nothing, and checks nothing for a send-only bus. With `verifyResources` it checks queues (`GetQueueUrl` with the owner account from the ARN) and subscriptions (a paginated `ListSubscriptionsByTopic`, whose `NotFound` means the topic is missing), at most `VERIFY_CONCURRENCY` (10) calls at once (`mapWithConcurrency`), plus the queue `Policy` with `verifyQueuePolicy`, collecting what's missing into one `ResourcesNotProvisioned`. Topics the bus only sends to aren't checked. An auth error on an external topic is logged as a warning (`SubscriptionCheck.Unknown`); other errors are thrown. It doesn't check queue attributes. `publishMessage` only creates the topic (`assertSnsTopic`, once per message) when `options.autoProvision` was set.
- **Topics you don't manage** (`getExternallyManagedTopicIdentifiers()`) are only subscribed to, by ARN; the integration test creates its system message topic itself.
- Config defaults use `??`, so an explicit `0` (e.g. `waitTimeSeconds: 0` for short polling) is honoured.
- `returnAddress` is the queue URL (from `queueArn`, or account + region + `queueName`), so repliers in other accounts and regions reach it. `sendToAddress` (for `ctx.reply()`) is an SQS `SendMessage` to that URL as is (a bare name is resolved in this transport's account and region), through a client for the URL's region when it differs from the main client's (the SDK only swaps the host and signs for the client's region; `regionalClients`, created once with the main client's credentials and retry settings, destroyed in `dispose()`, skipped for a custom endpoint like LocalStack), mapping `QueueDoesNotExist` to core's `EndpointNotFound`, with a body shaped like the SNS envelope (`Type`, `Subject`, `Message`, `MessageAttributes` as `{ Type, Value }`), so `readNextMessage` and bus-sqs-lambda read it unchanged. A requester still has subscriptions for the replies it handles, since every handled message is subscribed (reply-only handlers are #340).

## Retry and failure

- `TransportMessage.failedAttempts` is `ApproximateReceiveCount - 1` (`toFailedAttempts`, exported for bus-sqs-lambda).
- `returnMessage(message, delay)` sets the message's visibility timeout to `delay / 1000`, rounded and capped at `MAX_SQS_VISIBILITY_TIMEOUT_SECONDS` (12 hours). The redrive policy (`maxReceiveCount`) is only a backstop for messages that crash the process; core's recoverability policy dead-letters through `fail`.
- `fail(message, failure)` copies the message to the DLQ with the `bus-failure` metadata as an SQS message attribute (one, so it stays within the limit of 10), and then deletes it, so it gets a new MessageId and its receive count resets. Unparseable messages go the same way. `bus-failure` is a reserved header name.
- Receiving takes one message at a time. If more than one arrives, they're all made visible again and nothing is returned.
- Message attributes are carried as SNS attributes named `attributes.<k>`, `stickyAttributes.<k>`, `correlationId`, `messageId`, `sentAt` and `replyTo`. `fail` and the redrive policy copy the SNS envelope, so they survive dead-lettering; `TransportMessage.id` stays the SQS `MessageId`, which changes on `fail`. `endpointName` is `queueName`, or the name from `queueArn`. Booleans use DataType `String.boolean` (SNS has no boolean type and rejects `Boolean`). `false` and `0` are kept; empty strings, `undefined` and `null` are dropped because SNS rejects empty values. `fromMessageAttributeMap` is exported because `bus-sqs-lambda` uses it.
- Headers set by outgoing middleware (`TransportSendOptions.headers`) become SNS message attributes under their exact names (`toHeaderAttributeMap`), typed like attributes. `correlationId`, `messageId`, `sentAt`, `replyTo`, `bus-failure` and names starting `attributes.`/`stickyAttributes.` are reserved and throw `TransportHeaderReserved` from `assertSendOptions` and `toHeaderAttributeMap`. `deadLetterSqsMessage` copies the body, so headers survive `fail`. AWS's limit of 10 message attributes only applies with SNS raw message delivery, which bus-sqs doesn't use.
