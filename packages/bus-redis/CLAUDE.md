# bus-redis

A Redis Streams transport (node-redis 6, a peer dependency), replacing the archived `node-ts/bus-redis` 0.x (Redis lists via modest-queue: 0.1.8 for bus-core 1.x with `new RedisTransport({ connectionString })`, and 0.1.1–0.1.7/0.1.9 for bus-core 0.6 with inversify's `BusRedisModule`). The design was agreed on #347 (see the "Accepted design" comment). Read the root `CLAUDE.md` first.

## Design

- **Config** (`src/redis-transport-configuration.ts`): `queueName`, `connection` (node-redis `createClient()` options minus `RESP`/modules/scripts/typeMapping, default `{}`), `keyPrefix` (default `bus`), `visibilityTimeoutMs` (30 s), `deadLetterRetentionMs` (14 days; `0`/`Infinity` keep everything). No `deadLetterQueueName`: dead letters are per queue. `queueName`/`keyPrefix` with `{`/`}` or empty throw `InvalidRedisKeyName`; durations must be whole milliseconds (Redis rejects a fractional `IDLE`), else `InvalidRedisTransportDuration`. Using it before `connect()` throws `RedisTransportNotConnected`.
- **Connections**: `connect()` makes the command client (`createClient({ ...connection, RESP: 2 })`, so raw replies always have RESP2 shapes; everything goes through `sendCommand`, `multi().addCommand()` or scripts). node-redis' command timeout stops covering a command once it's written to the socket (6.3, `commands-queue.js`), so a frozen or half-open connection would leave a read or script pending forever. So every client gets `socket.socketTimeout` (15 s; the reader's is at least the block time + 10 s), `pingInterval` 5 s (so idle connections aren't timed out; hence `+ping` in the ACL) and a `reconnectStrategy` that also reconnects after a socket timeout (node-redis' default doesn't); settings in `connection` win. `stop()` races the fetch in flight against 3 s and then `destroy()`s the reader, and bounds giving back messages to 3 s; `disconnect()` bounds leaving the group and `close()` to 3 s each, then `destroy()`s (`settleWithin`/`closeClient`). The integration test freezes a TCP proxy (`src/test/freezable-proxy.ts`) during a blocked read to cover it. `start()` makes the reader with `duplicate()`. Every client has an `error` listener. Only standalone Redis/Valkey (no Cluster or Sentinel in v1), but keys stay Cluster-ready.
- **Keys** (`src/redis-keys.ts`, internal): `<prefix>:{<queue>}:queue` (stream, consumer group `<queue>`), `<prefix>:{<queue>}:delayed` (zset), `<prefix>:{<queue>}:dead-letter` (stream), `<prefix>:subscriptions:<$name>` (set of queue names). Every script touches one queue's keys only, which share the `{<queue>}` hash tag. `escapeGlob` escapes ACL key patterns.
- **Entries**: fields `body` (serializer output), `attributes` (JSON), `headers` (JSON) and `failedAttempts` once returned; the dead letter copy adds `bus-failure` and drops `failedAttempts`. Only `bus-failure` is a reserved header. `TransportMessage.id` is the entry id (new on each retry).
- **Sending**: `SMEMBERS` the subscription set, then one `MULTI` of `XADD <queue> NOMKSTREAM * …` per subscriber (all or nothing on a single primary). No subscribers warns and drops; a null reply (stream missing) warns. `sendToAddress` is `XADD NOMKSTREAM`, `EndpointNotFound` on null or an address with braces.
- **Scripts** (`src/redis-scripts.ts`, run with `EVALSHA`, falling back to `EVAL` on `NOSCRIPT`; they use the server's `TIME` and only Redis 6.2/7.0 commands so Valkey 7.2+ works; don't use `XACKDEL`, `XNACK` or `XREADGROUP CLAIM`): every settle checks `isPendingTo` (pending to this consumer with the delivery count it was read with, the lease token) and returns 0 if not, which the transport logs as taken over. `DELETE` = XACK + XDEL. `RETURN` = ZADD a `cjson` copy `{id, fields}` at now + delay (or XADD at once when the delay is 0) + XACK + XDEL. `FAIL` = XADD to the dead letter stream with `MINID ~ now - retention` + XACK + XDEL. `MAINTAIN` (before each read) moves up to 100 due zset entries back with XADD, returns ms until the next is due, reclaims with `XPENDING … IDLE <visibilityTimeoutMs>` + `XCLAIM` (once per second, for as many reads as are waiting), and once a minute removes other consumers with nothing pending and idle for a day. `RELEASE` (stop) re-claims a read-but-unhandled entry with `IDLE <visibilityTimeoutMs> RETRYCOUNT <deliveries - 1> JUSTID`, so another receiver takes it straight over without an attempt counted. `LEAVE` (on `disconnect()`, after the bus' workers settled) `XGROUP DELCONSUMER`s this consumer only when nothing is pending to it: DELCONSUMER drops pending entries, so never run it otherwise.
- **Receiving**: one fetch at a time per transport (`fetchForWaiters`/`fetch`) for every waiting `readNextMessage()`: MAINTAIN, then reclaimed entries, or else `XREADGROUP … COUNT <waiters> BLOCK min(1000, next due) STREAMS <queue> >` on the reader. If converting or dead-lettering an entry of a batch throws, the entries not yet given to a read are released (`deliver`). It loops until a message or `stop()`; a fetch error rejects the waiting reads (`NOGROUP` becomes `ResourcesNotProvisioned`), so the bus logs it and backs off. `failedAttempts = failedAttempts field + deliveries - 1` (new reads have 1 delivery; a reclaimed entry has its XPENDING count + 1), so expired receipts count like SQS and Postgres. `stop()` waits for the fetch in flight (≤ 1 s), releases unhandled entries and resolves waiting reads with `undefined`; handlers still settle until `disconnect()`. The consumer name is `<hostname>-<pid>-<uuid>`, per transport. Unparseable bodies are dead-lettered on read.
- **Provisioning**: `provision()` (unless send-only or a dry run) runs `XGROUP CREATE <queue> <queue> 0 MKSTREAM` (`BUSYGROUP` is success) and `SADD`s every handled `$name` and custom-handler topic. `messageNames` is unused (no per-message resources). Plan types: `redis-stream`, `redis-consumer-group`, `redis-subscription`; `runtimePermissions` is `{ format: 'redis-acl', document: { user: '<runtime_user>', rules } }`: own keys RW, `%W~<prefix>:{*}:queue`, `%R~<prefix>:subscriptions:*`, and the commands the transport and its scripts run (send-only: just the two patterns + `xadd smembers multi exec ping`). The integration test runs a bus as an ACL user with exactly these rules, so keep the list in step with the scripts. `initialize()` with `verifyResources` (not send-only) checks `XINFO GROUPS` and `SISMEMBER`s and throws `ResourcesNotProvisioned`.
- Delayed sends use the persistence's outgoing messages and dispatcher (no core change). The transport doesn't join the `withOutbox()` transaction.

## Tests

- Integration tests need Redis at `redis://localhost:6380` (override with `REDIS_URL`): `docker compose up -d --wait redis` from the repo root (port 6380, since 6379 is often taken). Valkey is on 6381 (`docker compose up -d --wait valkey`, `REDIS_URL=redis://localhost:6381`); CI runs the integration file against both. Tests use a random `keyPrefix`, remove only their own keys with `SCAN`/`UNLINK`, and must never `FLUSHDB`/`FLUSHALL`: the server may be shared. The ACL test creates and deletes its own user.
- The suites use bus-test's fixtures and message types, so this package has no `generate:message-types` script. `src/test` only holds the freezable proxy.
