Add `dispatched` to the outgoing middleware context, for sends, publishes and replies: a promise that resolves once the message reaches the transport, which for a message sent from a handler is when its outbox is flushed after the handler resolves, and for a message sent with `deliverAfter` or `deliverAt` is once it's stored. It rejects with the transport's error if sending fails, or with the new `OutgoingMessageDropped` (with an `OutgoingMessageDropReason`) if the message is never sent, because a middleware didn't call `next()`, the send was rejected before the transport (a middleware threw or a header was reserved, kept as the drop's `cause`), the handler failed or called `failMessage()` or `returnMessage()`, or another message in the outbox failed to send first. A delayed message rejects with the persistence's error if storing it fails, and as `duplicate` when the persistence skips it because a message with the same `messageId` is already stored. A rejection nothing observes is ignored. The send and publish contexts also get `dueAt`, when a message sent with `deliverAfter` or `deliverAt` is due. Incoming and handler middleware get `requestedSettlement()`, which returns `RequestedSettlement.Failed` or `RequestedSettlement.Returned` once `failMessage()` or `returnMessage()` has been called for the message, so middleware can tell such an attempt from a successful one after `await next()`. A message buffered in a handler's outbox is now sent in the async context its outgoing middleware called `next()` in, so a tracing span started around `next()` is active for the transport call. When a message in an outbox fails to send, the flush now waits for the outbox's other sends to finish before the handler fails.
