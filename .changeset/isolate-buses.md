Every bus is now isolated from other buses in the same process, and is given its message types with `withMessageTypes()` instead of reading a global registry (#299).

- **Breaking:** message types are passed to each bus with `Bus.configure().withMessageTypes(...messageTypes)`, which takes the `messageTypes` export of one or more generated files and can be called more than once. `registerMessageTypes()` and `getMessageTypes()` are removed from `@node-ts/bus-messages`, along with the registry on `globalThis`. `mergeMessageTypes()` merges several the way the bus does, and `MessageTypesConflict` now names the two generated files that conflict.
- **Breaking:** the file generated by `bus generate-message-types` no longer registers its types when it's imported. It only exports `messageTypes`. Regenerate it, and pass it to your bus. The generator's warning when nothing imports the file now says to pass it to `withMessageTypes()`.
- **Breaking:** every bus that receives messages (handlers or workflows, polling or with a receiver) must have message types for each message it handles and each workflow state it persists, whichever serializer it uses, or `initialize()` throws `MessageTypesMissing`, whose help says how to pass them. Send-only buses and buses with no handlers aren't checked.
- **Breaking:** a bus used inside another bus' handler no longer inherits the `correlationId` and sticky attributes of the message being handled, and its `failMessage()` and `returnMessage()` throw `FailMessageOutsideHandlingContext` / `ReturnMessageOutsideHandlingContext` instead of acting on the other bus' message through its own transport. Each bus has its own handling and lifecycle context, and `messageHandlingContext` is no longer exported: use `bus.getHandlingContext()` to read the message a bus is handling.
- **Breaking:** a transport instance can only be used by one bus, since it holds one queue and one connection. `build()` throws the new `TransportAlreadyInUse` for a transport another bus uses.
- **Breaking:** serializers and persistence can be shared by several buses. `Serializer.deserialize` and `toClass` take the bus' message types as an optional last argument, and `JsonSerializer` holds no state. Persistence adapters store and return plain JSON values, and the bus restores workflow state with its own serializer and message types, so `@node-ts/bus-postgres` and `@node-ts/bus-mongodb` no longer use `coreDependencies.serializer`. A shared persistence is disposed when the last bus that uses it is disposed. `CoreDependencies` gains `messageTypes`.
- **Breaking:** `defaultLoggerFactory` is replaced by `createDefaultLoggerFactory()`, so each bus has its own logger cache.
- `@node-ts/bus-test` exports its fixtures' generated `messageTypes`, which its suites pass to their buses.
