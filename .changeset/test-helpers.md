Add test helpers for handlers and workflows, described in the new [Testing](https://node-ts.github.io/bus/guide/testing) guide (#265):

- `handlerContext(overrides?)` makes a fake `HandlerContext` that records what a handler sends, publishes and replies with in `sent`, `published` and `replied`, each with the options it was given, such as `deliverAfter`, and a reply with its `destination`. It sets `messageFailed` or `messageReturned` when the handler calls `failMessage()` or `returnMessage()`. `sentOf(Type)`, `publishedOf(Type)` and `repliedOf(Type)` narrow the recorded messages to one type so their fields can be read. It checks what the bus checks: `send` and `publish` throw `InvalidDeliveryOptions` for a `deliverAfter` or `deliverAt` the bus would reject, and `reply` throws `DelayedReplyNotSupported` when given either, and `ReturnAddressMissing` when given `replyTo: undefined`. Replies go to `TEST_RETURN_ADDRESS` unless a `replyTo` is given. It works for function and class handlers.
- `workflowContext()` records and checks the same way, takes its `correlationId` and return address from the `attributes` it's given, and also sets `completed` or `discarded` when a handler calls `complete()` or `discard()`.
- `testWorkflow(workflow, options?)` runs a class workflow or one declared with `defineWorkflow` without a bus. `when(message, attributes?)` delivers a message to the scenario's instance and returns what the handler sent and the state as the bus would have saved it, with the bus' merge, complete, discard and mapping rules. `given(state)` starts from a saved state, and `advanceTime(ms)` moves the scenario's clock on and delivers the delayed messages the workflow sent itself, such as timeouts, with the correlation id and return address the bus would give them. It keeps a delivered message scheduled when its handler throws or returns it. It throws `MessageNotHandledByWorkflow` for a message the workflow doesn't handle, `WorkflowFactoryMissing` for a class workflow whose constructor takes arguments without a `createWorkflow` option, and `advanceTime()` throws `InvalidTimeAdvance` for a negative or non-finite time.
- `InMemoryQueue.idle()` resolves once nothing is queued, being handled or waiting to be retried, so a test can await it instead of listening for its handlers. It rejects with `InMemoryQueueDisposed` if the queue is disposed with messages left in it.

A bus no longer sleeps 500 ms after a read that comes back empty when the read itself waited that long, so a message sent to an idle bus over the in-memory queue or SQS, whose reads wait for a message, is handled straight away instead of up to 500 ms later.
